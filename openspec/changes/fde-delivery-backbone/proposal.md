# Proposal: 交付骨架

## Why

现有工作台能记录项目和八阶段，但“推进阶段”仍只是一次确认：没有本阶段必须产出的材料、没有可核对的证据、没有 Revise/Narrow/Stop 与返回重评，也没有项目组合视图和项目首页。结果是工作台更像记录表，Agent 和人都无法判断“现在缺什么、下一步谁来决定”。

两个参考仓库已经把答案验证过：FF 的八阶段合同要求每阶段 4 个工作项、3 份必需产物、由 Host 计算评审阻断项，阶段推进只能由 FDE 作出决定；gxfde 则证明项目中心、任务、资料库和文档版本是交付团队真正每天使用的对象。本变更先把这套“交付骨架”落进现有插件，后续增量再补调研工作区、方案/验证/收口与 DSH 原生能力。

## What Changes

- **数据模型 v2 与迁移**：从单一 `workbench.json` 的 v1 项目记录升级为按项目隔离的 `.fde/` 结构；保留现有项目、阶段备注、机会、会议，迁移必须幂等且不丢数据。
- **项目组合与项目首页**：新增项目中心（筛选、搜索、交付周期、阶段分布、待人工决定、下一动作）和项目首页（业务缘由、关键人、成功标准、风险、近期证据、阶段路径）。
- **八阶段合同**：每个阶段固定 4 个工作项、3 份必需产物（第一阶段另有一个可选产物）；阶段有 `working` / `blocked` / `review-ready` 状态，评审就绪由宿主按产物、证据、阻塞和决定确定性地计算。
- **评审与四类决定**：Go / Revise / Narrow / Stop；记录决定人、理由、证据摘要与 revision。Go 只推进一格，Revise/Narrow 留在本阶段，Stop 关闭项目；不再有“记录并继续”的隐式推进。
- **返回重评**：允许从当前阶段退回上一阶段，必须填写原因；保留全部产物与历史，并标记需要重新确认的范围。
- **资料库与来源**：项目内上传/登记文件，保存大小、哈希、版本与相对路径；支持文本/Markdown/CSV 预览，证据和产物可以引用来源。
- **任务与轻量甘特**：项目任务支持状态、优先级、负责人、起止日期和前置依赖；提供列表/看板视图与跨项目任务中心。
- **文档版本**：交付文档从模板创建，支持 `draft` / `review` / `approved` / `archived`、版本历史、Markdown 正文与恢复。
- **项目工作区导航**：项目内固定为概览、阶段、任务、调研、文档、资料、活动；保留现有 AI 机会与会议，并让它们可以关联到项目和阶段。
- **助手创建项目**：助手在对话中把“帮我创建一个项目”解析成待确认的项目卡；只有用户确认后才写入并打开项目，没有名称或日期非法时不创建。AI 不可用时仍可通过助手的「新建项目」表单直接创建。
- **BREAKING**：v1 数据的字段与目录布局升级为 v2；工作项由每阶段 3 个变为 4 个；旧的“阶段决定并继续”操作被四类决定取代。

## Capabilities

### New Capabilities

无。本变更只修改既有能力，不引入新的 spec 边界。

### Modified Capabilities

- `fde-workbench-shell`: 从“单面板 + 侧栏入口”扩展为“项目组合 → 项目首页 → 项目工作区”的导航与页面结构。
- `fde-workbench-records`: 项目元数据与组合视图、八阶段合同与固定产物、评审与四类决定、返回重评、资料库、任务、文档版本，以及 v1→v2 迁移。
- `fde-workbench-ai`: 上下文助手从“严格只读”扩展为“既有记录只读，但可生成并确认一个项目创建提案”。

## Impact

- **宿主**：`src/host/schema.js`、`state.js`、`store.js`、`files.js`、`routes.js`、`migrate.js`，新增阶段合同、项目元数据、资料、任务、文档版本的处理与路由。
- **客户端**：`src/client/store.js`、`selectors.js`、`ui/app.js`、`projects.js`、`stage-panel.js`、`overview.js`、`docs.js`，新增项目中心、项目首页、阶段合同、任务、资料库与文档版本界面。
- **数据**：`workbench.json` 升级到 schema v2；新增 `projects/<id>/.fde/`、`fde-deliverables/`、`sources/`、`documents/` 等目录；旧 v1 数据自动迁移。
- **测试与文档**：新增 schema/迁移/阶段门禁/决定/返回/任务/资料/文档版本测试；更新 README、数据布局与 agent 说明。
- **不在本变更内**：调研对象树与动态表单、方案设计、架构/API/图谱、验证/Eval、试点/生产/验收、项目多会话、Skills、实验室、主题。这些留给增量 2–4。
- **不做**：多用户角色、MySQL/Redis、对象存储、病毒扫描、微信/ClawBot、LCSC 与企业管理后台。
